Privacy & analytics

Last updated: 14 November 2026

WeatherOrbit is a static weather app published on GitHub Pages. This page explains the visitor measurement it performs and the choices you have. It is written to be read, not to hide behind legal wording.

Short version: WeatherOrbit uses Umami Cloud, a cookieless analytics service. Every page loads Umami's standard tracker snippet; the app reuses it for section and event analytics without loading a second copy. No cookies are set and no account is linked to a visit. To opt out, block cloud.umami.is or disable JavaScript; the plain snippet does not honour Do Not Track or Global Privacy Control.

What is measured

When a page loads, the Umami tracker sends one pageview, and each change of section sends another; a generated city guide sends one pageview of its own. It records:

  • The page path and title. On the app and city guides the query string and hash are excluded, so a shared link such as ?city=Tokyo is counted as the page, not as the city you looked at. The plain static pages record the URL as loaded.
  • Which section you are using — City Search, Compare, Climate Filter or Live Cameras. The app is a single page, so these are sent as virtual paths such as /WeatherOrbit/compare; switching sections is not a request to another page.
  • Generated city guides — one pageview per guide, such as /WeatherOrbit/cities/tokyo, with its own title and climate summary.
  • The referring site (the page that sent you here) and the site hostname.
  • Approximate location — country, region and city — derived by Umami from the network address. This is not GPS and is often less precise than a city.
  • Technical context: browser, operating system, device type, screen size and browser language.
  • An anonymous session identifier, calculated on Umami's server. It is described below.

How visitors are counted

Umami does not store an identifier in your browser. Instead, its server hashes the website ID, the visitor's IP address, the browser's user agent and a secret salt. The salt rotates monthly. The IP address is processed to calculate that hash and to look up the approximate location, but it is not stored as a field in the analytics record.

Two consequences are worth knowing. Because the salt rotates, the same person is counted again after the rotation, and changing network or browser can also start a new session. Because the identifier is derived from the network and browser, two people behind the same office network on the same browser may be counted as one. Treat "visitors" as a trend, not as a count of people.

As with any hosted service, Umami and its infrastructure providers may process IP addresses transiently in operational or security logs. That is separate from the analytics record, which has no IP field.

What is not collected

  • No cookies and no advertising identifiers.
  • No name, email or account is linked to a visit. WeatherOrbit never calls Umami's identify() function, and accounts and saved cities are not used for analytics.
  • No query strings or URL fragments on the app and city guides; the remaining plain pages record the URL as loaded.
  • No cross-site tracking: Umami's identifier includes this website's ID, so it cannot join a visit to another site.
  • No selling of data, no advertising and no personalisation based on analytics.

Interactions recorded

Donations and feedback are sent as custom events (for example donate_click when a visitor opens the Ko-fi or PayPal donation page, or helpful_vote when they answer "was this helpful?"), not as pageviews. Events carry no personal information. They are sent by the app's section tracker, which skips its own calls when the browser sends Do Not Track or Global Privacy Control; the plain snippet's basic pageview is unaffected by those signals.

Why the data is kept, and for how long

The measurements answer practical questions: which pages are used, which countries and cities visitors come from, and whether the site works on phones. The free Umami Cloud plan keeps analytics history for six months. Aggregate data can be exported from the Umami dashboard.

Who processes it

  • Umami Cloud receives the pageview and provides the analytics dashboard. Its data region (United States or European Union) is chosen when the account is created.
  • GitHub Pages serves the static site and, like any web host, sees requests to it.
  • Open-Meteo provides the forecast data shown by the app. Your browser requests it directly when you search for a city.
  • Google Fonts supplies the typeface used on the page, so your browser requests the font files from Google.

Your choices

  • Do Not Track is checked by the section/event bridge, which then sends no extra calls. The plain Umami snippet does not check it, so a basic pageview is still sent.
  • Global Privacy Control has the same effect: the section/event bridge stays silent, but the plain snippet still sends a basic pageview.
  • A content blocker that blocks cloud.umami.is prevents measurement. The app works exactly the same.
  • JavaScript disabled also prevents measurement, because the tracker never runs.
  • You can ask questions or raise a concern through the project's issue tracker.

Donations and feedback

Donations go to the maintainer through an external fundraising page (Ko-fi, PayPal.Me or GitHub Sponsors). Clicking the button only opens that page in a new tab; WeatherOrbit does not send the click anywhere else, and no donation data is shared with the analytics service.

Feedback and bug reports are handled through the project's public issue tracker. The optional "was this helpful?" vote is sent as a custom analytics event with no personal data attached; it never identifies the visitor.

Changes

If what is measured changes, this page and the date above will change before the new measurement is enabled. The Umami configuration is public in analytics-config.js in the WeatherOrbit repository, so the description here can be checked against the code.
